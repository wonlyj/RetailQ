# 第五章标注与评估规则

21条意图样例为开发者编写的七类各3条；12条工作流样例为同一演示语料上的功能验收与已知回归，不是生产流量样本或无偏保留集。标签按当前主要意图人工编写：明确投诉优先；退款退货先政策；单纯查配送与“先订单后物流”组合归物流；维修换货归售后；邮费/商品规格归商品咨询。

T8真实运行前冻结样例、两个Prompt、代码/依赖/模型配置、语料和实际加载策略的SHA-256；不可用样例重新拟合阈值。语料缺少对应事实时不得为通过而编造答案或补标签；修改问题或Prompt后新目录重新评估，旧报告保留。

意图要求21/21符合标签；端到端12例分别核对真实节点、申请/执行回执、流终态、引用可定位及每项事实。随机业务数据只与本次实际回执比较，不要求固定状态。缺订单号必须追问，不能猜1001；来源demo必须说明演示。控制约束（必检索、闸、无自动工单）不能靠正文关键词代替执行证据。

W06为弱证据候选题，相关性分数可能被“退货政策”词命中抬高，故真实运行必须检查实际门槛结果；若未触发弱分支，不能把“回答不足”记作弱证据闸已验证，另用已冻结的低分测试依赖验证确定性分支，并记录真实语料下这一题的局限。W10相关但缺失事实允许前置闸通过，随后必须明确证据未说明，不捏造瓦数；这不代表完整可回答性闸已实现。

投诉未确认时SQL工单增量必须0；转人工模拟无工单请求；W12经明确确认后仅1票据且会话未自动标转人工。同动作重复确认、两按钮顺序、继续聊天、刷新/换会话/未知结果由代码/人工指南验收，分别保留证据。未完成、未评或无DB核查不报全部通过。Prompt质量只在真实模型结果和人工语义核对后下结论。
