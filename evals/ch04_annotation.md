# 第四章评估数据标注说明

这是一份演示知识库上的作者标注集，不代表真实企业规则。事实以 `examples/knowledge/manifest.json` 所列的规范化 Markdown 版本为准；`source_version` 是规范化正文 UTF-8 的 SHA-256，`section_path` 是完整 Markdown 标题路径，`quote` 是能够在该章节实际切块内逐字找到的支持片段。不会把数据库自增 ID 写进标注，评估器须用冻结版本映射。

`ch04_cases.jsonl` 包含 A_policy、B_model、C_colloquial、D_missing、E_multi 各 20 题，每桶前 4 题为 calibration，其余 16 题为 test。`family_id` 标识同一事实族，不能跨两个 split；多事实题按其涉及的事实判断是否共享 split。`required_facts` 列出问题要求的事实；可答题的 `relevant_groups` 每组列出满足该事实的等价来源，多个组均须覆盖。缺失题的 `required_facts` 明确缺少的信息，来源组为空，不能把空组误算成充分证据。实际运行时还需验证当前快照和数据库块与这些标注一致。

作者检查了具体型号、否定、断电条件、价保和退货的不同起点、外套和垫芯、会员基础运费和偏远附加费、退款不能承诺具体到账日期。未知型号和积分有效期属于缺失信息；对于退款到账，已知的是不承诺具体天数，而实际到账日期仍未知。运费按用户确认统一为未满 99 元基础运费 10 元，偏远附加费另计。

`ch04_prompt_checks.jsonl` 的 `expected_useful` 表示提供的证据是否足以回答，`expected_claim_supported` 表示样例答案的断言是否受证据支持，二者独立。空答案的断言支持度为 null；P20 是证据充分但样例拒答的反例。错误答案是专门供裁判验证的人工构造，不是客服真实输出，也不应进入长期编造台账。

作者逐条核读问题与对应证据并用本项目实际 BGE tokenizer 切块复核：100 题、20 条 Prompt 样例、20/80 划分、68 个不跨 split 的事实族，以及全部引用版本、章节和片段匹配 53 个实际块。该检查证明标注与当前来源对齐，并不证明模型会遵守 Prompt、四策略效果或忠实度裁判准确；这些须在后续真实模型运行中验证。
