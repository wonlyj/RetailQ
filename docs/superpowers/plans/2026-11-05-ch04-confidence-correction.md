# 第四章置信度纠偏实施计划

> **For agentic workers:** Use superpowers:executing-plans; Native 执行。按任务记账并逐阶段更新 dev-notes/ch04.md。

**Goal:** 纠正相关性与可回答性的混淆，降低口语问题误拒，同时验证缺失信息拒答。

**Architecture:** 为冻结的真实检索候选标注独立相关性，校准器按策略的首位候选相关性拟合门槛；生成阶段继续自评证据充分性。用新问题族的保留样本、真实服务和人工事实核对评估，符合验收条件后才更换隔离配置。

**Tech Stack:** Python、现有 Milvus Standalone BM25 + RRF、SiliconFlow BGE-M3 及 BGE reranker、现有聊天模型与 MySQL。

**Spec:** `docs/superpowers/specs/2026-11-05-ch04-confidence-correction-draft.md`

## Global Constraints

- 保持已约定选型与两阶段拒答、来源和低置信度问题池；不使用旧测试集或反馈问题拟合门槛。
- 阈值需由人工标注的校准集拟合，身份与评估数据冻结；新测试按问题族隔离。
- 真实运行不可用或安全验收未通过则保留旧策略并诚实报告。
- 每完成阶段立即追记 dev-notes/ch04.md；不清除已有服务和数据。

## Review Focus

- 相关但不可答的候选必须按相关性标注，不按答案是否存在标负例（任务 1）。
- 缺失、重复、未知、非布尔标签或错配的候选不能用于拟合（任务 1）。
- 旧策略、语料、检索实现或标注身份变化不能静默复用新策略（任务 1）。
- 评估集的问题族不得跨校准和新测试；反馈问题仅作回归（任务 2）。
- 新阈值不得使缺失问题编造事实；人工核对与池记录均需要真实证据（任务 3）。

### Task 1: 建立独立相关性校准

**Files:** Modify `scripts/calibrate_rag.py`, `retailq/knowledge/policy.py`; test `tests/test_rag_calibration.py`。

**Interfaces:** 提供 `fit_relevance_policy(calibration, annotations)` 返回 `ConfidencePolicy`；annotation 每条绑定 eval_id、strategy、候选 id、明确布尔相关性及说明；无候选由明确空候选标注。

- [ ] 先写测试：相关但不可答的高分候选为正例；完整证据但首候选无关为负例；漏标、重复、候选 id 变化、缺说明或非布尔值拒绝拟合。
- [ ] 运行测试确认因功能缺失而失败；实现分策略平衡准确率拟合并在相同得分下选择更保守阈值，拒绝类别不足。
- [ ] 运行单项测试与原校准测试；将检索、重排、校准规则纳入策略身份，使变化须重校准。
- [ ] 完成后记账并更新开发记录。

### Task 2: 冻结样本和相关性标注

**Files:** 新 `evals/ch04_relevance_*` 标注及问题样本；必要时新增独立评估脚本和测试，禁止覆盖历史评估文件。

- [ ] 按规格创建标注规则及按问题族隔离的校准、保留集，覆盖口语同义词、相近型号、相关但缺属性、完全无关、多段证据、禁止承诺；验证引用来源和分集，冻结哈希。
- [ ] 在隔离语料上执行真实四策略检索，按规则人工标注每个校准候选的首位相关性，保留 id、理由和运行身份；先完成数据再计算阈值。
- [ ] 仅用校准集拟合门槛，记录类别数量、阈值与局限；原用户邮费作为单独回归题。
- [ ] 完成后记账并更新开发记录；如相关性样本或环境不足，记录阻塞，不制作假标注或模拟真实结果。

### Task 3: 真实评估、回归和交付

**Files:** `docs/ch04-evaluation.md`, `docs/ch04-calibration.md`, `dev-notes/ch04.md` 及独立运行记录。

- [ ] 先冻结验收规则：口语可答题不少于 80% 正确作答，所有缺失事实题和禁止承诺题均不得编造；所有作答引用可定位且无知识拒答能入池。列出样本数；样本量过小不得声称线上泛化。
- [ ] 冻结策略后跑新保留集真实聊天与四策略检索；逐题人工核查事实、引用、拒答及入池，不把自动裁判替代人工核查。
- [ ] 原邮费问题、型号、发票、缺失及退款问题跑真实回归；做完整自动测试和代码审查。
- [ ] 通过才在隔离环境发布新策略，保留旧策略与报告；记录命令和部署方式。未通过保持现状并如实报告。
