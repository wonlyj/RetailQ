# 第六章正式分流器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让现有客服 Workflow 正确处理多轮指代与意图切换，并以订单优先、政策必查、LangGraph 原轮暂停恢复完成退款/售后判断及用户确认的退款工单。

**Architecture:** 保留既有服务、上游与 AsyncSqliteSaver，在同一图中加入查询处理和核心业务节点。检索侧按同一快照合并查询并统一重排；选单以持久化 interrupt 暂停，经归属校验后 Command(resume=...)。退款复用原动作和工单事务，前端在后端契约稳定后直接 Vibe Coding。

**Tech Stack:** Python 3.12、FastAPI 0.159.1、SQLAlchemy 2.1.6、LangGraph 1.2.20、langgraph-checkpoint-sqlite 3.1.3、langchain-core 1.6.13、langchain-openai 1.7.2、pymilvus 3.0.2、原 MySQL/Milvus/BGE-M3/bge-reranker-v2-m3。

**Spec:** `docs/superpowers/specs/2026-11-09-ch06-router-design.md`（2026-11-09 用户已批准）。

**Status:** 2026-11-09 独立计划评审通过；首轮2项Important已修订并由同一审阅者复核关闭。用户已确认按此计划进入Native实施；T1–T8后端实施、真实评估及唯一独立后端review修复已完成；最终本地交付收尾，GUI按用户指示委托执行、待反馈。记录：`docs/superpowers/reviews/2026-11-09-ch06-plan-review.md`。

## Global Constraints

- 只做大模型默认分类，沿用现有聊天上游；不做小模型降级、训练或跨会话记忆。
- 指代消解与 Query 改写合并使用 LLM；完整、明确且标准的问题原样保留，口语模糊问题才做必要归一，不为改写而改写。
- 意图输出恰好 intent/confidence；七类选择题另加“其他”兜底。confidence 为有限 [0,1] 数值，不能是布尔值。
- 退款退货与售后遵循订单 → 检索侧扩写 → 强制政策检索 → Agent；通用规则 FAQ 也先拿订单，但单查询、不扩写。
- 扩写输出恰好 queries 数组，2–4 条；原独立问题另行保留参与召回；不在入库侧复制知识。
- 缺订单号采用 LangGraph interrupt/checkpointer 暂停，resume 继续同一个 turn_id；不能伪装成新聊天轮。
- 不增加服务组件。前端直接 Vibe Coding，不套 brainstorm/TDD/code review。后端可测试代码走 TDD；Prompt/数据以冻结标注样例评估代替 TDD。
- 每个阶段即时追加 dev-notes/ch06.md，记录用户关键原话、关键产出、拒绝/纠偏、翻车/返工。
- 涉及框架/库/API 的实现前先查 Context7，并核对锁定版本接口；额度耗尽时按用户规则查官方文档，记录回退与实际版本。不得擅自替换已定技术。
- 固定演示订单目录同时提供卡片与 query_order；不增加订单表。退款表单仅创建 ticket_type=退款、status=待处理的申请。
- 直接本地 main；不创建 PR。保留已有历史记录和策略文件，不删除 MySQL 卷，不清空演示库。

## Review Focus

4. **多查询中途换语料、耗尽 deadline 或返回重复来源**：同快照、去重、共享截止、失败不带半套证据进 Agent；T3 故障检索测试覆盖。
5. **客户端绕过退款表单调用旧通用工单端点**：绑定退款动作仍必须校验固定原因与订单，不让文本字段绕过；T6 HTTP/事务测试覆盖。

### Task 1: 查询/分类协议、Prompt 与冻结语义评估

**Files:** Create `retailq/workflow/router_contracts.py`, `retailq/workflow/query_processing.py`, `retailq/prompts/workflow_resolve.txt`, `retailq/prompts/workflow_query_plan.txt`, `retailq/prompts/workflow_expand.txt`, `evals/ch06_router_cases.jsonl`, `evals/ch06_annotation.md`, `scripts/evaluate_router.py`, `tests/test_router_protocols.py`; Modify `retailq/workflow/classification.py`, `retailq/gateway.py`, `retailq/workflow/contracts.py`, `retailq/workflow/repository.py`, `retailq/prompts/workflow_intent.txt`, `tests/test_workflow_classification.py`, `tests/support/workflow_upstream.py`。

**Interfaces:**
- New frozen dataclasses in router_contracts.py: `IntentResult(intent: str, confidence: float)`、`QueryPlan(core_case: bool)`；JSON parser outputs use these or primitive values, never arbitrary models in persisted State。
- `parse_intent(text: str) -> IntentResult`（classification.py）；`parse_resolution(text: str) -> str` accepts only resolved_question；`parse_query_plan(text: str) -> QueryPlan` accepts only core_case；`parse_queries(text: str) -> tuple[str, ...]` accepts only queries。
- Gateway: `resolve_query(messages, *, max_tokens: int, observer: RouterObserver | None = None, call_id: str | None = None) -> tuple[str, UsageCharge | None]`；`plan_query(...) -> tuple[QueryPlan, UsageCharge | None]`、`expand_query(...) -> tuple[tuple[str,...], UsageCharge | None]`、`classify_intent(...) -> tuple[IntentResult, UsageCharge | None]`采用相同kwargs。Protocol与受控gateway一并更新，不对共享gateway临时设置全局observer。
- `RouterObserver = Callable[[dict], Awaitable[None]]`定义在router_contracts.py；每次请求使用独立call_id（复用预算reservation_id），依次await observer：raw阶段包含stage/call_id/raw_content/finish_reason/tool_calls/usage，必须在plain-text/JSON/finish校验前写；随后同ID记录parsed阶段的JSON可序列化值，或invalid阶段的error_code；未收到response的transport_error保留错误码而不假造raw。内部记录不改变公共intent/confidence输出。
- `WorkflowRepository.record_router_observation(turn: TurnRef, observation: dict) -> None`将不可覆盖的raw及后续状态放payload.router_calls[call_id]；runtime给每个turn的QuerySteps/IntentClassifier注入绑定该TurnRef的observer，复用write_sql并等待落库。纯prompts CLI用绑定case_id的文件observer，不依赖业务库；回调失败不得继续伪报评估通过，公共error不含raw。
- `QuerySteps(gateway, settings, *, deadline, observer: RouterObserver | None = None)` exposes async `resolve(state) -> dict`, `plan(state) -> dict`, `expand(state) -> dict`；`IntentClassifier(gateway, settings, *, observer: RouterObserver | None = None).classify(state) -> dict` produces intent、confidence、route、agent usage。
- `resolve_output_cap(raw_question: str, settings) -> int`位于query_processing.py，计算保守预算或抛ServiceError(422)；T5的prepare在start_turn/流响应前调用，QuerySteps及prompts CLI复用，不到模型请求后才发现固定cap不足。
- State adds confidence、query_plan、queries；resolved_question is the current independent question. A helper `resolved_messages(messages: list, raw_question: str, resolved_question: str) -> list` replaces only the current user request for execution while preserving trusted history/system and raw SQL message。
- CLI stage `python -m scripts.evaluate_router prompts --output <new-dir>` evaluates resolution, intent, core_case planning, expansion without requiring the UI; it must preflight the explicit configured upstream and never print secrets。
